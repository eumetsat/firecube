    Ingest From A STAC API

    Ingest the granules of one collection of a STAC API instead of a local directory or an S3 prefix.

    When To Use This

    Use this page when a STAC API, such as Earth Search, publishes the source granules your plugin reads. Firecube searches the collection and hands the plugin the location of each data asset. Everything after discovery runs as for a local source.

    Prerequisites

    • Firecube and a compatible plugin installed in the same environment, with the stac extra:
    source .venv/bin/activate
uv pip install 'firecube[stac]'
    • The plugin can open the asset locations the API publishes. When the plugin opens an asset through Firecube, an https:// or http:// href is downloaded to the workspace of the run. The download happens the first time the plugin opens the asset. It is anonymous: Firecube sends no signature and no credentials. Firecube reads an s3:// href with the storage settings of the run. A public bucket, such as the one behind cop-dem-glo-30, needs --storage-anonymous. A private bucket uses the credentials in Configure S3 Access. Firecube refuses an href with any other scheme it cannot open.
    • The API supports STAC item search. A static catalog.json catalogue is not supported.

    Steps

    1. Name the collection as a stac:// URI. Take the API landing page URL, replace https:// with stac://, and append /collections/<id>:
    API landing page Collection Source
    https://earth-search.aws.element84.com/v1 cop-dem-glo-30 stac://earth-search.aws.element84.com/v1/collections/cop-dem-glo-30

    The URI has no ? and no #. Pass one collection per URI.

    1. Run the ingestion. --stac-search takes one JSON object with any of the keys datetime, bbox, intersects and ids:
    firecube ingest PLUGIN_NAME \
  --input-data stac://earth-search.aws.element84.com/v1/collections/cop-dem-glo-30 \
  --stac-search '{"bbox": [11.5, 48.0, 11.7, 48.2]}' \
  --target file:///data/products/dem.zarr \
  --product-name dem \
  --storage-type local \
  --storage-driver fsspec \
  --storage-anonymous \
  --write-mode direct

    Firecube reads every result page and keeps each asset whose roles contain data. The default file-suffix list does not apply.

    Instead of the flag, you can set a stac_search table in the plugin configuration. It takes the same keys. firecube ingest, firecube zarr preallocate and firecube zarr slots all read it. If you pass --stac-search, the flag replaces the whole table.

    To keep only some assets, add --input-filters. It matches the last segment of each href. This command keeps only the assets that end in _DEM.tif:

    firecube ingest PLUGIN_NAME \
  --input-data stac://earth-search.aws.element84.com/v1/collections/cop-dem-glo-30 \
  --stac-search '{"bbox": [11.5, 48.0, 11.7, 48.2]}' \
  --input-filters '["*_DEM.tif"]' \
  --target file:///data/products/dem.zarr \
  --product-name dem \
  --storage-type local \
  --storage-driver fsspec \
  --storage-anonymous \
  --write-mode direct
    1. To read several collections, or a collection and a local directory, repeat --input-data. Each value is a file://, s3:// or stac:// URI. --stac-search applies to every stac:// source:
    firecube ingest PLUGIN_NAME \
  --input-data stac://earth-search.aws.element84.com/v1/collections/cop-dem-glo-30 \
  --input-data file:///data/raw/extra-tiles \
  --stac-search '{"datetime": "2021-01-01T00:00:00Z/2021-12-31T23:59:59Z"}' \
  --target file:///data/products/dem.zarr \
  --product-name dem \
  --storage-type local \
  --storage-driver fsspec \
  --storage-anonymous \
  --write-mode direct

    Firecube ingests a STAC asset once when two stac:// sources return it. Two results are the same asset when the collection, the item id and the asset key match. The first source wins. A file-tree href and a STAC asset with the same href are not merged. The order of the sources does not change the order of the granules.

    Verify

    Read the start record of the run. The run_started event holds the key meta.stac_discovery. Its sources list the stac:// URIs. Its search is the filter as given. Its item_ids list the collection/item_id of each STAC item that discovery found. firecube zarr preallocate records the same key.

    grep '"run_started"' /data/products/dem.zarr/.firecube/runs/*/events-*.jsonl

    Expected result: one line per run, each with a stac_discovery object. Replace the path with the directory of your product.

    To read the status of the run, list the runs of the product:

    firecube chunks runs list --target file:///data/products/dem.zarr

    Expected result: one run with status complete. Open the product with the plugin's usual check, for example the output summary that firecube ingest printed.

    Troubleshooting

    Symptom Cause Fix
    Error: No source files found after applying input filters. The search matched no item, or no asset with the data role survived --input-filters Widen --stac-search or --input-filters. Check the collection's assets on the API's /collections/<id>/items page
    Invalid value for '--input-data': stac:// URI path must end in /collections/<id> The URI names the landing page, /search or an item Append /collections/<id> to the API root
    Invalid value for '--stac-search': ... accepts only the keys datetime, bbox, intersects, ids The filter holds another key, for example collections or limit Remove the key. The collection comes from the stac:// URI
    --stac-search applies to stac:// sources only, and no --input-data names one. No --input-data is a stac:// URI Drop --stac-search, or add a stac:// source
    stac_search in the plugin configuration applies to stac:// sources only, and no --input-data names one. The plugin configuration holds a stac_search table and no --input-data is a stac:// URI Remove the table, or add a stac:// source
    Firecube cannot open ftp:// sources: ftp://host/file.nc The plugin opened an asset href through Firecube, and Firecube cannot open its scheme, here ftp:// Use an API that publishes https:// or s3:// assets, or open the asset in the plugin
    firecube ingest requires the stac extra pystac-client is not installed Run uv pip install 'firecube[stac]'
    Unable to locate credentials Firecube read a public s3:// asset without credentials Pass --storage-anonymous
    Cannot search STAC source stac://... The API did not answer, or refused the search Open the landing page in a browser and retry; check the host and API root
